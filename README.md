# Тестирование производительности OpenVPN: ГОСТ vs AES-256-CBC

Экспериментальное сравнение алгоритмов шифрования в OpenVPN на стенде под управлением ALT Workstation 10.4.

## Алгоритмы

- **Null Cipher** — туннель без шифрования (baseline архитектурных накладных расходов)
- **AES-256-CBC** — промышленный стандарт с аппаратным ускорением AES-NI
- **ГОСТ Р 34.12-2015 «Кузнечик»** — российский стандарт (программная реализация)

## Основные результаты

| Режим | Throughput (Мбит/с) | Латентность avg (мс) | CPU (%) | Деградация относительно AES |
|-------|---------------------|----------------------|---------|------------------------------|
| Baseline | 549,8 ± 159,1 | 1,717 | — | — |
| Null Cipher | 20,16 ± 0,34 | 2,935 | 36,5 | +1% |
| AES-256-CBC | 19,94 ± 0,34 | 2,611 | 60,6 | — |
| ГОСТ Кузнечик | 7,27 ± 0,30 | 3,414 | 94,0 | **-63,5%** |

## Стенд

- **ОС:** ALT Workstation 10.4 (ядро 6.1.115-un-def-alt1)
- **OpenVPN:** 2.6.19
- **OpenSSL:** 1.1.1w (11 Sep 2023)
- **GOST-engine:** 1.1.0.3.0.255
- **Виртуализация:** VirtualBox (2 vCPU, 3.8 ГиБ RAM, драйвер e1000)
- **Аутентификация:** Static key (pre-shared)

## Параметры конфигураций

### Общие параметры (все режимы)
- `tun-mtu 1400` — размер MTU туннельного интерфейса
- `mssfix 1360` — корректировка MSS для предотвращения фрагментации
- `secret /etc/openvpn/static.key` — статический ключ (pre-shared key)

### Различия по режимам

| Режим | cipher | auth (HMAC) | Длина ключа |
|-------|--------|-------------|-------------|
| Null Cipher | `none` | `none` | — |
| AES-256-CBC | `AES-256-CBC` | `SHA256` | 256 бит |
| ГОСТ Кузнечик | `grasshopper-cbc` | `md_gost12_256` | 256 бит |

## Выводы

1. **Архитектура OpenVPN** — основное узкое место: падение throughput в 27 раз даже без шифрования
2. **AES-256-CBC** — минимальный оверхед (<1%) благодаря аппаратным инструкциям AES-NI
3. **ГОСТ Кузнечик** — снижение производительности на 63,5% из-за отсутствия аппаратной оптимизации в процессорах x86_64

Для практического применения ГОСТ в высоконагруженных VPN рекомендуются криптоакселераторы или переход на ядерные реализации туннелирования (например, WireGuard с поддержкой ГОСТ).

## Методология

- 5 прогонов iperf3 по 10 секунд для каждого режима
- ping -c 100 для измерения латентности
- pidstat для мониторинга загрузки CPU
- 95% доверительный интервал рассчитан по t-распределению Стьюдента (n=5, df=4, t=2,776)
